# Roomba+ 4.2.12

## Mission elapsed time reads *Unknown* between missions

4.2.11 was meant to make **Mission start** and **Mission elapsed time**
read *Unknown* while no mission is running. Mission start did. Mission
elapsed time kept a number on the dock (@nareso).

That number was not the last mission's duration. The sensor worked out
"now minus the mission's start time", and the robot keeps that start
time after the mission ends. Docked, the sensor showed the time since
the previous mission *started*, recalculated whenever the robot sent a
status update: 748 minutes, in the report. The test that should have
caught it described an idle robot without that start time, which a
real robot never is.

Both sensors now ask the same question the **Mission active** binary
sensor asks, in one shared place, so the three cannot disagree.

**The last mission's duration** is its own sensor: **Missions – Last
duration**. It is computed the same way — end minus start — once, when
the mission finishes.

## Both stay filled during a mid-mission recharge

A robot that docks to top up during a long mission reports `charge`
while its mission carries on. Mission start used to read *Unknown*
there, as if the mission had ended. With the shared check it keeps the
start time, and Mission elapsed time keeps counting.

A paused mission still reads *Unknown* on both, as Mission active reads
off: the robot reports a paused mission as stopped.

## Under the hood

- **hassfest rejected two error messages** that put their placeholder in
  single quotes. In the message format Home Assistant's frontend uses, a
  single quote before a placeholder turns it into literal text, and
  hassfest now refuses it. All eight languages now quote the value in
  their own style — “…”, „…“, « … » — and a test applies hassfest's rule
  to every language, not just the two files hassfest reads
- **Four tests passed only because another test file ran first.** They
  imported the integration as `…roomba_plus.__init__`, which without
  that earlier file is not the integration at all. Run on their own,
  they failed. A diagnostics test patched a second copy of the module
  the same way and so replaced nothing. All now import the package, and
  a guard rejects the pattern
- Comments and test notes that still named two test files merged away
  in an earlier release now name where those tests live
