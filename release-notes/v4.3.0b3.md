# Roomba+ 4.3.0b3

**A beta.** Everything in [4.3.0b2](v4.3.0b2.md), plus the fixes from
the stable release [4.2.15](v4.2.15.md). Nothing else changed since b2.

Needs *Show beta versions* in HACS. Built on **roombapy-prime 0.4.0b2**,
as b1 and b2.

---

## From 4.2.15

- **No carpet boost control on robots without carpet boost.** An i7
  offered a **Carpet boost** select that snapped back to *eco* on every
  change. Carpet boost is now offered only when the robot declares it
  in its capability list (`cap.carpetBoost` is 1), as the 980 and the s9
  do. On other robots the select and the **Setting – Carpet boost**
  sensor are removed, and the vacuum no longer offers fan speeds.
- **No false room-cleaning warning on a 900- or 600-series.** A Roomba
  980 logged at every start that iRobot credentials or smart zones would
  make room cleaning available. A robot that keeps no map between
  missions cannot clean single rooms, so it now gets a debug line, and
  the diagnostics give the reason `no_persistent_map`. Whether a robot
  keeps maps is read from its capability list.

- **A room the robot only reached into is not a cleaned room.** A room
  behind a closed door came back from the cloud as finished, with 4 of
  106 sq ft (the doorway strip). A room event now counts as cleaned only
  when it covered at least 10 % of the room.
- **Room coverage in the REST mission list.** `room_coverage` was always
  null; it now carries each room's covered share from the mission's own
  room events.

- **A recorded mission shows up at once.** The vacuum's last cleaned
  rooms follow a mission recorded by Roomba+ itself without waiting for
  the robot's next status message.
- **Naming Smart Map zones without an iRobot account.** The dialog shows
  each zone's ID inside its field and explains how to find out which
  zone is which, instead of pointing to a rooms map that stays empty
  without an account. The empty rooms map now says why it is empty.

- **Room times learned from every mission, per cleaning mode.** Mission
  progress, the current room and the time left use how long each room
  took in the cloud's own room events, in the mission's mode (vacuum,
  mop or both). A Braava no longer falls back to the average of whole
  missions.
- **Rooms guessed without a room signal wait for the cloud.** On a robot
  that reports neither position nor drives (a Braava) with an iRobot
  account, a multi-room mission's rooms come from the cloud's room
  events instead of a guess.

Details: [4.2.15 release notes](v4.2.15.md).
