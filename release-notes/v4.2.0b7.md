# Roomba+ 4.2.0b7

Everything in b1 through b6 still applies. This adds what also went out
as 4.1.8.

> **Check your automations if any of them read the readiness sensor.**
> Its state used to be English text (`Ready`, `Off dock`); it is now a
> key your language translates for display (`ready`, `off_dock`). A
> comparison against `"Ready"` stops matching, and it stops silently.

## The readiness sensor speaks your language now

**Status – Readiness** showed English text in every language. The
translations existed all along, in all eight — the sensor produced a
value none of them could match, so not one of the 73 ever appeared.

## And it was naming the wrong states

Two testers' robots reported a value shown as "Off dock" while sitting
on their docks, charging. It means the robot is loading a map
(@Thonno, @ScenicSystemsLLC). The table is now taken from the robot's
own firmware rather than a formula, and twenty-two more everyday states
are named — bin full, insufficient charge, tank low, map version
mismatch among them.

Unconfirmed values show as their raw number rather than an invented
name. Guessing is what caused the above.

## Mission results are translated

`stuck_and_resumed` and its five siblings appeared as raw text in every
language. All six are translated in all eight now.

## Cleaning rooms by name could fail for rooms that plainly exist

`roomba_plus.clean_room` could answer "Unknown room(s)" for rooms
visible in the selector at that moment (@mrsnyds). The display reads a
cached name list; the service read only the map data, and saw nothing
when that was empty. It now falls back to the same cache — except on
multi-map robots, where the cache cannot say which map a room is on.

## `clean_zone` no longer accepts a room name

It resolved names against a list holding every region on the map, rooms
included, and sent a room's id as a zone. The mirror image of the bug
fixed in 4.1.6; both directions are now closed.

---

## Still what this beta is for

The async rewrite has met little hardware. **The failure to watch for is
a command that silently does nothing** — the robot does not move,
nothing appears in the log.

Settings changes on i/s robots are the least-tested part: passes and
suction never worked there before this line, and nobody has yet
confirmed they hold.
