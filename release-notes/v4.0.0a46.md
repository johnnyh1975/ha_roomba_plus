# Roomba+ 4.0.0a46

Requires roombapy-prime 0.3.0b17, which comes with the HACS update.

The status sensor is the headline: it now says things it could not say
before, in your own language, and the same things on both robot
generations.

## Status now tells you what the last thing you read was worth

Two states were missing, and both had been visible only to someone who
already suspected them.

**Charging mid-mission.** A robot that returns to top up reports
`charge` while its cycle is still running. As plain "Charging" that is
indistinguishable from a finished mission, and an automation reacting to
it fires mid-clean. The distinction existed as its own binary sensor,
which meant finding it required knowing to look for a second entity
beside the one that says what the robot is doing.

**No contact.** A robot that stops transmitting keeps every entity
showing its final value, indefinitely. One tester's S9+ went `stuck` off
its dock, drained for six hours, declared battery-low and went silent at
36%. Nine days later the status still read "Stuck" as though it had just
arrived, and the battery still read 36.

The silence was recorded the whole time — a link watchdog had been on
since minute five. It lived in a separate binary sensor, so knowing the
status was nine days stale required already suspecting it was.

The threshold here is an hour, deliberately far above the watchdog's
five minutes: that answers "is the link healthy", this answers "should
you still believe this".

## The status is translated now

For as long as this sensor existed it showed English to everyone. Classic
translated in code — one language, hard-wired. Prime reported the robot's
raw firmware words, which have no language at all.

Both now report translation keys, and the same ones: a single set of
state translations serves both generations in all eight languages.

**This changes the entity's value.** Automations match `charging` rather
than `charge` or `Charging`. That is a break, taken deliberately while
this is still alpha rather than after a stable release — the alternative
was a fourth entity for the same robot state, or never doing it.

Fifteen phases the vacuum entity could already map had no label at all
and reported as unknown. They have one now.

## Diagnostics no longer leak the robot's id

Every credential-shaped field was redacted and the blid still appeared in
clear text, inside `map_id` — which is `<blid>-<epoch>`, a secret hiding
as a substring of a composite value under a key that does not sound
sensitive.

Substring redaction already existed, written after an earlier report of
exactly this shape in a different field, with a docstring saying that
redacting the field called `blid` while leaving copies elsewhere is worse
than not claiming to redact at all. It had been applied to one section.

It now covers the whole payload. A diagnostics download exists to be
attached to a public issue; one field leaking through a side door defeats
redacting it everywhere else.

## Also

- The cloud-coverage fallback for robots that report no pose was gated on
  the robot's declared `cap.pose` — which is precisely the field that
  lies on lewis firmware, where an i7 advertises pose and never sends
  one. It now checks whether a pose has actually arrived.
