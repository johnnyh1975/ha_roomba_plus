# Roomba+ 4.2.22

Classic room cleaning with zones, Prime per-room sensors and room names, and two additions to the room history: how long a room usually takes, and all rooms under one attribute.

## Classic: `clean_room` could clean a zone instead of the room you named

Rooms and zones are numbered separately, so a map can hold room `0` and
zone `0` at the same time. Roomba+ remembered whether an id was a room or
a zone by the bare id, reading rooms first and zones second. So the zone
overwrote the room, and a `clean_room` call for the room went out to the
robot as the zone.

@FJSoninC found it on a j7+: `clean_room: Hallway` cleaned a 9 sq ft
toilet zone in three minutes instead of the 305 sq ft hallway, twice in
a row. Deleting the zone in the iRobot app made the same call clean the
hallway.

- **Fixed.** A zone's name now resolves to an id that carries its type,
  the same way `clean_zone` and Prime robots already do it. A room and a
  zone with the same id each go out as what they are.
- **Affects `clean_room` and what is built on it, such as
  `clean_overdue_rooms`.** The *Clean selected room* button and
  `clean_zone` already sent the right type.
- **Not changed:** `last_cleaned_rooms` and the diagnostics still list the
  names you asked for, not what the robot cleaned. On a wrong run they
  showed *Hallway*; only the cleaned area gave it away.

If you deleted a zone in the iRobot app to work around this, you can
draw it again.

## Prime: no per-room sensors, and room numbers instead of names

@mrsnyds (Roomba 105) turned on *Separate sensor per room and zone*,
reloaded, restarted, and got no sensor at all, while the diagnostics
listed all nine room names. His *Rooms – Cleaning history* also showed
region numbers (`10`, `11`, …) after every restart until a cleaning
command, from Roomba+ or the iRobot app, made them names.

Both had one cause. On Prime, the room names are read from the map a few
seconds after start-up, and Roomba+ announces them when they arrive. That
announcement looked for Home Assistant on the config entry, which does
not carry it, so it was never sent:
- the per-room sensors were created only if the map happened to be read
  before the sensors were set up, which in practice was rarely;
- the history, which a robot at rest gives no reason to redraw, kept the
  numbers until the robot next sent something.

- **Fixed.** The per-room sensors appear as soon as the names are read,
  and the history and *Rooms overdue* switch to names at the same moment.
- **The names are now kept across restarts.** Until now every start-up
  began without them until the map had been read — a cloud call that
  can be slow or fail, made by the map entity, which can be disabled.
  From the second start-up on, everything starts with names.
- **The same mistake in two more places**, found by widening the check
  that should have caught it:
  - `clean_room` without a `cleaning_mode` was meant to use whatever the
    *Cleaning mode* selector shows, and never did;
  - on Classic, the maintenance baseline set when a part is first seen
    was never saved, and was set again after every restart.

## How long a room usually takes

*Last cleaned – room* has two new attributes:
- `typical_duration_min`: the median time the robot spent in that room
  over its newest 10 cleans;
- `typical_duration_cleans`: how many cleans that is.

It is the same measure as `last_duration_min`. Every visit to the room
in one clean is added up, and charging, emptying the bin and the drives
to and from the dock are not counted. So a room the robot left halfway
to recharge counts only the time actually spent in it. The median keeps
one clean that was cut short or got stuck from moving the figure. It is
not split by cleaning mode, so on a Combo, vacuum and mop runs share it.
@mrsnyds had been building this from status changes and tracker updates.

The per-room sensors also read the mission history once per update
between them now, rather than once each. With nine rooms and a full
history that is about ten times less work on every update.

## Removing the integration removes the Prime map bundle too

The floor plan Roomba+ keeps for the Prime live map was the one file not
deleted when you remove the integration. It is now, along with the new
room-name file.

## The cleaning history as one attribute

*Rooms – Cleaning history* also carries its rooms under one attribute,
`rooms`, so a template can list them without filtering out
`friendly_name`, `state_class` and anything Home Assistant adds later
(@mrsnyds). The flat attributes stay, so
`state_attr(history, 'Kitchen')` keeps working.

```jinja
{{ state_attr('sensor.<robot>_room_cleaning_history', 'rooms')
   | dictsort(false, 'value') | map(attribute=0) | list }}
```

This gives every room, oldest clean first.
