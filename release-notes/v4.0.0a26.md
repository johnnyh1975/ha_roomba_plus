# Roomba+ v4.0.0a26

Requires roombapy-prime **v0.2.0b13** — unchanged, no library update needed.

Two things the marker made visible, now that anyone can see it.

## The dock is drawn where the dock actually is

The map bundle records where the dock stood when the map was **built**, and nothing corrects it when
the dock moves. @utkjmitch's map put it on a spot now occupied by a treadmill, while the iRobot app
showed it correctly on the same map.

A bundle carries thirteen content files and `dockPose` is the only one with a dock in it — so there
was no fresher field to switch to. The app reads the robot, not the map.

**Which is the fix, and it was in reach all along:** a robot reporting `charge` is standing on the
dock, and its position arrives through the same stream in the same coordinates. That observation now
wins.

The bundle stays as the fallback rather than being dropped. It is there immediately on every
account, without waiting for a mission to end, and a remembered dock roughly in the right place
beats no dock at all on a fresh install.

The first point of a mission is also at the dock and was considered — but the position stream only
starts once it is asked for, by which time the robot has begun to move, while the last point while
charging is unambiguous.

## Schedules can be edited from the calendar

Creating and deleting worked; editing did not, because Home Assistant only shows a save button when
the entity says it supports it. Opening a schedule to shift it by an hour meant deleting it and
making another.

Room selection survives a time change. Calendar events are regenerated from the schedule rather than
stored, so what the dialog opens with is already the canonical room labels — and those parse back to
the same rooms.

**Editing a single occurrence is refused.** A robot schedule has no notion of "this one only": every
run comes from the same rule, and applying such an edit to all of them would change days nobody
chose.

## Also

- **Two consumable counter types added** — `Battery` and `Sqft`, from the app's own enum. Neither has
  appeared in a catalogue response yet; the table now covers all seven types the app knows, so a
  robot reporting one gets a unit rather than a bare number.
- A guard that had been quietly failing since calendar editing was first built now has its exception
  recorded, with the reason: a Classic robot's calendar never edits schedules, because nothing writes
  `cleanSchedule2` yet.
