# Roomba+ 4.2.7

Three things 4.2.6 got half-right, found by running it.

## Your robot's own room times are now actually used

4.2.6 measured how long each room took and kept it. Nothing read it
back: the lookup gave up early whenever the cloud offered no estimates
at all — which is exactly the situation the measurement exists for, so
the one case it was built for never reached it.

Measured three times across three missions, logged as kept each time,
and every run still started with no estimates (@ScenicSystemsLLC).

## "Last cleaned rooms" reports rooms that were cleaned

The attribute read its room list from a source only cloud-connected
robots have. On a locally connected robot it found nothing every time
and kept whatever it last managed to resolve — all seven rooms of a
whole-house run were still listed after two later two-room missions.

It now uses the rooms room tracking actually advanced through, which
only became possible in 4.2.6. A mission cut short lists the rooms it
reached, not the ones it was asked for.

## Cloud failures at startup say what went wrong

If the first cloud fetch failed while Home Assistant was starting, the
log said so and nothing else — a rate limit, a name-resolution failure
during boot and a rejected login all produced the same sentence.

The reason is now in the message, with a full traceback at debug level.
The message also promised a retry without saying when; the cloud is
polled once a day, so it now says that, and points at reloading the
entry to get rooms back immediately.

## Diagnostics no longer contradict themselves about maps

4.2.6 added the active map version to the download and recorded it only
on cloud-connected robots. A locally connected one therefore read "not
read yet this session" while the same file carried correct versions a
few sections away.

The field was added so its absence would stop being mistaken for the
robot not reporting a map. Saying the wrong thing is worse than saying
nothing, so it now reads whichever source the robot actually has.

## The room dropdown survives a cloud outage

Cleaning a room by name worked without the cloud, because that path
reads the rooms Roomba+ has saved. The dropdown did not, so the same
rooms were reachable one way and missing the other at the same moment.

The dropdown now falls back to the same saved data. A room whose map is
unknown is still left out — sending one without its map is what produces
the "not reporting which map" refusal.

Nobody reported this; it came out of checking whether the fault above
had siblings elsewhere in the code.
