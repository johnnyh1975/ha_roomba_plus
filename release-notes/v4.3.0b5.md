# Roomba+ 4.3.0b5

**A beta.** Everything in [4.3.0b4](v4.3.0b4.md), plus the fix from the
stable release [4.2.17](v4.2.17.md), plus a clearer hint in the account
setup.

Needs *Show beta versions* in HACS. Built on **roombapy-prime 0.4.0**,
as b4.

---

## From 4.2.17: the maintenance to-do list for Classic robots

The maintenance to-do list has been opt-in since 4.0, but its switch
was only in the options of Prime robots. A Classic robot's list could
not be switched on at all. @ScenicSystemsLLC found it with three Classic
robots on one account:
- the one he removed and added again had no list;
- the other two still had one, but only as an `unavailable` left-over in
  the entity registry.

- **Classic robots have the switch now**: Configure → Connection
  settings → *Show maintenance as a to-do list*.
- **A switched-off list leaves nothing behind.** The left-over entities
  are removed on the next start.

## Setting up with your iRobot account: the robot's address

With the account, a Classic robot's password comes from the cloud, so no
HOME button is needed. Its address on your network does not. Roomba+
searches for it, and asks for it when the search finds nothing. That
happens with Home Assistant in a container without host networking, or
with the robot on another subnet.

The option's description said "needs no button press", and
@ScenicSystemsLLC read that as "finds everything by itself". It now says
that a robot connecting locally still needs its address, found or asked
for.
