# Roomba+ 4.6.7

**A failed local connection no longer locks the robot out until Home
Assistant restarts.**

Nothing to do: update and restart.

---

## A failed connection attempt is closed (@gloopy-purple-liquid, #265; #230)

A Classic robot takes one local connection at a time. When an attempt
to connect did not complete, the connection underneath stayed open: the
MQTT library roombapy uses (aiomqtt) does not close it when the robot
does not answer within its ten seconds, nor when Home Assistant stops
waiting. Roomba+ stops waiting in setup and in the setup dialog after
sixteen seconds.

That left the robot's one connection taken by an attempt nobody used.
Every later attempt then timed out as well, and a robot that was briefly
busy, for example while the built-in Roomba integration still had it,
stayed unreachable for Roomba+ until Home Assistant restarted. A
Reconfigure that failed made the next one fail too: after one, the
Combo Essential of @gloopy-purple-liquid refused every new connection
for minutes. The log in #230 shows the same pattern on a Roomba 694.

Why his first attempt fails at all is not solved by this. On a fresh
restart, with nothing else connected, Reconfigure still times out while
the same password connects from another computer; #265 stays open for
that.

Roomba+ now closes such an attempt as soon as it ends. When the setup
dialog gives up, the attempt still running ends within about ten seconds
and is closed then. Wait that long before trying again.

The fix belongs in roombapy and is proposed there
([pschmitt/roombapy#631](https://github.com/pschmitt/roombapy/pull/631)).
Until a roombapy release with it is installed, Roomba+ applies the same
change to the roombapy it loads, and steps aside once roombapy has it.
Python loads roombapy once, so Home Assistant's built-in Roomba
integration, if loaded, gets the change as well; it only affects what
happens after a connection attempt failed.

## Smaller fixes for an Essential set up from the account (@gloopy-purple-liquid, #265)

- **An Essential still set up as a Prime robot** failed setup with a
  bare library error. The entry now says what to do: Reconfigure it with
  the robot's IP address, and leave the password empty to take it from
  the iRobot account.
- **Reconfigure no longer blocks Home Assistant's event loop.** Home
  Assistant logged loading the system certificates as a blocking call on
  every Reconfigure of a robot on the local connection.
- **Downloading diagnostics of an entry that failed setup** raised an
  error. It now returns the entry's state, data and options, redacted as
  usual.

## Tested

- The full suite passes on Home Assistant 2025.5; the changed modules'
  tests pass on 2026.10. ruff, the typing baseline and the per-module
  coverage floors pass.
- The connection fix is tested against a stand-in robot that accepts the
  connection and never answers: with the change, both the timed-out
  attempt and the one the caller gave up on are closed; without it, both
  stay open. The same run with roombapy 2.0.2 and the setup dialog's
  sixteen seconds leaves no connection open once the abandoned attempt
  has ended.
- Each fix's test fails without it.
- Neither change has run on a robot yet.
