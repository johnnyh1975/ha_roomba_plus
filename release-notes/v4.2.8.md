# Roomba+ 4.2.8

## Mission progress stayed at 0% after a room finished

The percentage worked out how many rooms were done by dividing elapsed
time by an average room. A room cleaned *faster* than that average
therefore counted as no rooms done at all — the display moved to the
next room in front of you while the bar stayed at zero.

Room tracking already knew how many rooms were behind it. The
percentage now uses that, and fills the step for the room in progress
from the clock, so it keeps rising between transitions instead of
jumping once per room.

A room running past its estimate cannot push the bar into a room the
robot has not reached, and the figure never goes backwards.

Reported with the diagnostics captured mid-mission, which is what made
it obvious: room index 1, elapsed 10.9 minutes, percentage 0
(@Thonno).

## Housekeeping

A second, unused store of per-room times sat beside the working one:
written by a method nobody called, read by a method nobody called, and
saved to disk on every write. Building the room-time memory last week I
wrote a duplicate of one of those methods without finding it, which is
the real cost of dead code — it looks like the feature while not being
it.

Removed, along with four other functions nothing reached.

## Diagnostics say why a map has no room outlines

`aligner_aligned: false` told you the alignment failed and nothing
about why. Three different situations produced that same line: the
floor plan outline never arrived, it arrived with no door-shaped gaps
in it, or gaps were found and the match failed anyway.

Downloads now carry the outline point count and the number of door
candidates found in it, which separates the three.
