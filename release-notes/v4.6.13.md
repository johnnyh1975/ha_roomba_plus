# Roomba+ 4.6.13

**Small fixes from a review of the whole integration, most of them for
homes with more than one robot.**

Nothing to do: update and restart.

---

## A menu entry the docs promised

*Configure → Manually enter Smart Map zones* lets a Smart Map robot
without the iRobot account take room numbers and names by hand. The
step, its texts and three pages of docs existed, but no menu offered
it. It is in the menu of every Classic Smart Map robot now.

## Which robot

- **Warnings in the log start with the robot's name** wherever Roomba+
  knows which robot they concern, so a log with several robots can be
  read without guessing (@lloydbayley).
- **The presence events** `roomba_plus_all_away` and
  `roomba_plus_person_detected_during_clean` carry `entry_id` and
  `name`, as every other event does. Each robot has its own presence
  manager, so with two robots these events came twice, alike.

## Texts

- On a Prime robot, two binary sensors were both called *Start blocked*:
  one for the blocking sensors in Home Assistant, one for a fault on the
  robot. The second is *Fault blocks start* now. Its entity id does not
  change, and a name you gave it yourself stays.
- The SMBus count in the dock-contact and battery-contact repairs was an
  English sentence in every language's text; it is a translated line
  now.
- The blocking sensors step and a few labels were still English in
  French, Spanish, Italian, Dutch and Portuguese.

## The diagnostics leave out the robot's position

The download carried the robot's last position, in millimetres from the
dock. It is left out now unless debug logging is on for Roomba+, as the
path of the last mission already was. The download says it was left
out.

## Under the hood

- Two delayed saves had no flush when the integration unloads, so a
  reload could let the old write land after the new one: the path-turn
  counts and the Prime rooms map's live layers. Both write on unload
  now, and a repository check fails for any delayed save without one.
- A repository check fails for any repair issue about one robot whose
  id does not carry the robot's entry. 4.6.12 fixed four shared ids; a
  copy with one of them shared again had passed every test.
- The mission timer's flush on a Prime unload, in the code since the
  reload race was found, has a test now.
- One helper moved to a module of its own, which takes 25 modules out
  of an import cycle; the late-import check now sees indirect cycles.
- `event.py` sets `PARALLEL_UPDATES`, as the quality scale file said
  every platform does.

These came from an architecture and UX review and an independent second
review of the same code. Eight defects were built into a copy on
purpose; before this release two of them passed the whole test suite,
now every one that still applies is caught.

## Tested

- The full suite passes on Home Assistant 2025.5 and 2026.10; ruff, the
  typing baseline and the per-module coverage floors pass.
- Each fix has a test that fails without it. None of these changes was
  run on a robot; none changes what is sent to one.
