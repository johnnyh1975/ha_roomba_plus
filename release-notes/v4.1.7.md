# Roomba+ 4.1.7

## The room display now follows the robot

Roomba+ shows which room your robot is working on. Until now it worked
out room changes from a phase the robot reports between rooms — and
S9-series robots never report one. On those, the display stayed on the
**first room of the plan** for the entire mission while the robot worked
through the house.

@ScenicSystemsLLC took thirteen samples across a confirmed room boundary
to prove nothing changed there, then ran a 73-minute whole-house mission
sampling throughout.

**There is a second signal, and the robot has been sending it all
along.** It reports when it is driving rather than cleaning. A drive
that ends is a room boundary — and the display now advances on that,
whatever the phase does.

Two things made this safe to rely on rather than guess at. The iRobot
app names the value `Traveling` in its own code, and the robot firmware
sets it from an internal mode called `CLEANING_MODE_TRAVEL`. Two
independent confirmations of the same thing.

The advance happens when the drive **ends**, not when it starts: the
robot is in the new room by then. Driving also covers avoiding an
obstacle and re-finding its position, so counting departures would
count too many.

## A new attribute: `room_progress_observed`

The room index starts at the first planned room. Until a change is
detected, the name shown is a **plan**, and from outside it looks
exactly like a reading.

`room_progress_observed` says which one you have. `false` means the
robot has not been seen to move on yet.

## The cleaning-mode selector only offers what the robot can do

Every robot was offered all four modes — vacuum, mop, and both
combinations — regardless of its hardware. Picking a mopping mode on a
vacuum worked as far as the selector was concerned: the choice stuck,
and then the robot went off and vacuumed. No error, nothing in the log
(@chairstacker).

The robot reports which jobs it has. That is now used, so a vacuum lists
vacuuming and a Braava lists mopping. A robot that has not reported its
capabilities yet still sees all four rather than an empty list.

## Also fixed

**Cleaning a zone on a robot with two maps.** It failed with "this
robot has 2 maps and is not currently reporting which one it is on",
even though the zone's map was knowable. The lookup that resolves a
map from a region id is keyed by plain ids, and zones carry a prefix,
so it missed every time. Invisible on a one-map robot — the fallback
picks the only map (@chairstacker).

**A map with no version id is no longer skipped in silence.** Its zones
cannot be cleaned by name, and nothing in the log said so.

**`last_cleaned_rooms` no longer reports an earlier mission's rooms**
while a new one is running. A whole-house start carries no room list at
all, so nothing resolved and the previous day's rooms kept showing
(@ScenicSystemsLLC).
