# Roomba+ 4.1.3

One fix, and it is the one behind two reports that looked like different
problems.

## Every room was also offered as a zone

`available_rooms()` has returned map-qualified ids since 4.1.0 —
`<map>/<room>` — but the check that stops a room being repeated in the
zone list compared those against bare region ids. `MAP-A/11` never
equals `11`, so the check never matched and **every room was emitted a
second time** under a zone id.

Reproduced from @theChef163's diagnostics before it was fixed: 21
segments where 11 were meant.

**Why it looked like two different bugs.** The room/zone selector keys
its list by name, so it collapsed each duplicated pair back to one entry
— and a genuine zone whose name matched nothing was simply absent. That
is what @theChef163 reported: ten rooms, no zone.

The area-mapping dialog keys by id, so it showed both halves. That is
what @chairstacker reported: "they both still have rooms and zones in
them", and a count that never matched the selector's.

One line, two symptoms, and I read the second report as a description of
how the dialog groups things rather than as the bug it was.

## Rooms on other maps can be mapped to areas

Home Assistant's area mapping offered only one map's rooms — whichever
the cloud listed as active. A room on another floor could not be mapped
at all, and a mapping made while one map was active stopped working when
that changed: the clean command dropped the unrecognised prefix without
a word.

Room targeting by name has resolved the map per room since 4.1.0; only
this path was left behind. Rooms from every map are offered now, each id
carrying its own, and a stored id is sent to the map it names. Rooms
from two floors in one command are refused rather than half-cleaned.

## A bin evacuation could open a phantom mission

Sending a robot home while it is already home runs an evacuation, and
during it the phase alternates between charging and running while the
cycle stays `evac` — with the running messages carrying the *previous*
mission's id, possibly days old. Roomba+ decided a mission had started
from the phase alone.

Established by a controlled test rather than inferred: one dock command
to a robot at 100% on its dock, nothing sent before or after, every
packet captured (@AlakazipLabs).

**Worth knowing, and now documented:** `vacuum.return_to_base` on a
docked robot empties the bin, because that is what a dock command means
when the robot is already home.

## A counter was named after something nobody has seen

`robot_lifted` in the mission API was derived from the robot's pick-up
counter. @AlakazipLabs retracted his own earlier claim that the counter
witnesses a lift: eight of ten increments had no wheel-drop reading, six
of those fell inside a dock-contact window, and it did not move when he
placed the robot on its dock by hand.

The number stays — it correlates with missions that went wrong — and now
also appears as `pick_events`, named for what was measured.
`robot_lifted` is unchanged for anything already reading it.

## Two things in the log

**Diagnostics always said "no rooms map entity"**, whether one existed
or not — the lookup used a different id shape from the one the entity
registers under. Two people sent files carrying that note while their
map was on screen and working, and it sent me looking in the wrong place
twice.

**A deprecated Home Assistant call** was naming this integration in
everyone's log, with a deadline of 2027.8. The replacement does not
exist in HA 2025.5, the minimum supported here, so the call is now
chosen at runtime: the new one where it exists, the old one otherwise.

## Cleaning a room on a floor the robot is not on

Not blocked — a robot carried upstairs is exactly the case that would
break — but a mismatch is now written to the Home Assistant log when the
command goes out, naming both maps.

The robot reports which map it is on only while it knows where it is; on
its dock it reports nothing, which is when people press buttons. So the
last reported map is remembered, and the log says whether an answer is
the robot speaking or the last thing it said.
