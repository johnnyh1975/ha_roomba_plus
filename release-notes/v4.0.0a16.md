# Roomba+ v4.0.0a16

Field reports from five testers, and one bug that had been quietly breaking mission history since it
shipped.

## Mission history never worked

`MissionStore.query()` requires a `days` argument. Three call sites omitted it, so every one raised
`TypeError` before doing any work:

- the mission sync's duplicate check — so **every sync since the feature shipped failed on its first
  line**
- the same sync's statistics update
- the diagnostics summary, which caught the error and reported a healthy store as `unreadable`

This is why "Missions – Last", "Last result", "Last duration" and "Area cleaned today" stayed empty.
One bug, four sensors.

It took two reports to find: one tester saw sensors that never filled, another's diagnostics said
the store was unreadable. Neither points at the cause alone.

## The rooms map was unavailable on several robots

`get_map_metadata()` returns room names, types and cleaning defaults — but on several models **no
geometry at all**. The map read outlines from there only, found none, and reported itself
unavailable rather than showing a blank canvas.

Outlines come from the map bundle now, with metadata as the fallback. Room names too: one tester's
app showed four rooms while the API returned a name for only three.

Three models, three testers, three independent routes to the same conclusion.

## The schedule calendar showed "Off" during a scheduled mission

Fixed once already, and still broken: the ongoing-occurrence logic was correct but the parser only
computed **weekly** schedules. A one-off — the shape an automation creates — produced no occurrences
at all, so the right logic ran on an empty list.

Weekly and one-off are computed now. Bi-weekly and monthly stay out: both need a cadence anchor the
payload does not supply, and putting a mission on the calendar for a day the robot does not clean is
worse than leaving it off.

**Worth knowing:** if an automation starts a clean directly rather than creating a schedule, there
is no schedule to show and "Off" is correct. The calendar reflects what the robot has planned, not
what Home Assistant is doing right now.

## Diagnostics were leaking identifiers

Redaction worked on **key names**. A field called `blid` was redacted; `p2map_id` — which is
literally `<BLID>-<epoch>` — was not, and MAC addresses sat under keys the code had never seen.

That is worse than no redaction, because it invites trust the output has not earned. It now matches
on **values**: the BLID replaced as a substring wherever it appears, MAC addresses matched by shape,
both at every nesting depth.

## New: dock controls

Empty bin, wash pad, stop pad drying — matching the iRobot app's own dock panel, gated on the dock's
reported capabilities.

The wire strings were confirmed from the app's own annotations rather than guessed. `drypad` exists
too and is deliberately absent: drying starts on its own after mopping, and a button for something
the app never triggers manually would be inventing a workflow.

## New: the room map updates during a mission

The live map stream carries a second URL alongside the raw occupancy grid, and it returns a full map
bundle. Found by **[@jouwdan](https://github.com/jouwdan)** (PR #63), who also established the
map-bundle geometry above and brought the Roomba Max 705 into the tested set.

## Smaller fixes

- **Detected pad** now shows "All pads fitted" / "Pad missing" instead of raw wire values, and
  accepts all seven pad categories — a robot reporting a pad *type* would previously have displayed
  `reusableWet` verbatim.
- **Seven migration steps removed.** Versions 3 to 9 renamed entity_ids from an early release, built
  from one installation's registry — 400 hardcoded ids, all carrying one robot's prefix. Entries
  still on those versions jump to version 10 and receive every later migration.
- **Eco charging** carries no capability gate, and that is correct: the app's capability list has 113
  entries and not one mentions charging. The app cannot gate it either.
- Duplicate helper functions merged — a slug rule existed three times, once nested and invisible to a
  module-level search, using a different unicode test than the other two.

4,612 tests passing.
