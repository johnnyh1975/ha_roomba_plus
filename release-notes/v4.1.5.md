# Roomba+ 4.1.5

Two additions to the diagnostics download. No behaviour changes.

Both close gaps that cost a tester a round trip: they were asked for
information the download did not contain, and had to work it out by hand
instead.

## Which robot owns which map

A cloud map entry carries `robot_ids` and a `shared` flag. The download
listed map ids and dropped both, so a household with more than one robot
could not answer whether a map is genuinely shared between them —
@ScenicSystemsLLC compared the id lists manually to rule it out.

`pmap_ownership` now reports the ownership of each map.

## What the robot says about its own mission

`missionTelemetry` is in the state of every i/s robot, and this
integration reads it nowhere. Room progress is inferred from phase
changes instead, which works on `lewis` robots and leaves `soho` ones
showing the first planned room for an entire mission.

The download listed the key name and nothing else, so what is inside it
could only be seen by asking for a raw state dump. The value is included
now, alongside the live `mssnNavStats`.

This does not fix the frozen room display — it makes the next
diagnostics download able to answer whether the robot reports its own
progress, which decides whether that display can be driven by data
instead of inference.
