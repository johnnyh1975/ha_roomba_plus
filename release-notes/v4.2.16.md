# Roomba+ 4.2.16

## A mission's rooms in the order they were cleaned

The cloud sends a mission's events **newest first**. Both real captures
show it: an i3+, and a Braava jet m6 mission exported by
@ScenicSystemsLLC (Guest Bathroom first, then Bedroom 2). Several places
read that list front to back, as if it were in order:

- **Cleaned rooms were listed in reverse.** The vacuum's
  `last_cleaned_rooms`, the REST mission list and the export named the
  last room first. The Braava mission came out as "Bedroom 2", "Guest
  Bathroom".
- **The time figure of the room accessibility score was always empty.**
  Time per room is the gap between one room's event and the next. Read
  backwards, every gap was negative and was dropped, so the score was
  built from coverage and stuck events only.
- **The mission path and the archived event timeline ran backwards**,
  and so did the room events in the diagnostics download.

All of them now sort the events by time first. Missions already in the
archive count too: the time figure and the path sort what is stored.

Not affected: the learned room times from 4.2.15. They sorted the
events from the start, and the Braava mission gives exactly the figures
expected (233 s and 742 s).

## Documentation: the built-in Roomba card that cannot be dismissed

With Roomba+ installed, Home Assistant keeps finding your robot for its
built-in Roomba integration. The **Discovered** card fails to open
(`Invalid handler specified`), and it cannot be ignored either, because
ignoring starts the same setup flow that fails to load (@FJSoninC). The
troubleshooting guide used to suggest ignoring it. It now explains why
that fails, and the README links there. The card is harmless; the
workaround in the guide removes it.
