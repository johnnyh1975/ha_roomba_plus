# Roomba+ 4.2.20

For dashboards that put the robot and its rooms on a map — the
Roomba+ card first among them —, a naming form for 900-series robots
that can be read at a glance, and one wrong room name in an event.

## The robot's position in the maps' frame

The maps draw the robot with its x and y axes swapped. The firmware's own
client always did this, and so do the cleaning path, the coverage grid,
the door markers and the stuck pins. The tracker's `x_mm`/`y_mm` keep the
firmware's order, so a dashboard placing the robot on a map had to know
to swap them.

- **New on the tracker: `map_x_mm`/`map_y_mm`,** the same point in the
  maps' frame. `x_mm`/`y_mm` are unchanged.
- **One conversion.** The maps and the tracker now take the swap from the
  same function, so the two cannot drift apart. A test fails if the map
  pipeline converts the pose on its own again.

## A recurring error named the wrong room

`roomba_plus_error_recurrence` names the room an error keeps happening
in. It looked the stored error position up without the swap, so it named
the room at the mirrored point. That was invisible only where x and y
happen to be equal, which is where its test put the error. It now uses
the maps' frame.

## Rooms on the map carry the names the room select shows

The `rooms` attribute of *Room map* and *Cleaning path* named each room
with the name in the map's own floor plan, which can be empty where the
account names the room. The room select puts your alias from
*Zone management* first. A room you had renamed was one thing in the
list and another on the map, and a tap on the map could not be matched
to the list.

- **Same names as the select, from the same source:** alias, then the
  account's name, then a name typed in the naming notice, then `Zone N`.
- **Each room also carries `region_id`,** the robot's own id for it.
- `room_id` stays the slug of the name, and is still the id for
  xiaomi-vacuum-map-card. A configuration generated earlier keeps
  working, because `clean_room` still takes the original name and its
  slug.

## Prime: room or zone

*Select room or zone* lists rooms and zones together, and the names do
not say which is which. **New attribute `segment_type`:** `room` or
`zone` for every entry, read from the entry's id — including a zone the
map lists among its rooms. It is there even when the floors could not be
named.

## Naming areas on a 900-series robot: a picture you can read

@liblit's screenshot of *Name detected areas* on a 980 needed four
questions to decode: dashed boxes, dotted lines, blue circles and a
green-and-blue dot, all on the live map. The boxes were each area's
outer bounds, widened past the walls; on an L- or U-shaped floor they
overlap, and one of nine covered half the picture.

- **The form now draws the areas themselves:** each one as the floor it
  consists of, in a colour different from its neighbours, with its
  number — or its name, once it has one — inside it. The dock is the
  green dot. Path, coverage outline and door markers are left out.
- **The text says what the picture shows,** and that it is drawn from
  the dock, so it may be turned against your floor plan.
- **"8 area(s)" is gone** from both naming forms, in all eight
  languages; the forms list the numbers instead.

The *Cleaning path* map itself is unchanged.

## Diagnostics: obstacle zones on the map

Robot-observed obstacle zones (`observed_zones`) are read from a centre
point on each zone. The only real map with such zones we have seen
describes them as outlines, with no centre point. If that holds, the
`zones` map attribute, the obstacle pins of `format=hazards` and the
`observed_zones` count on the zone summary sensor stay empty while your
map has zones, and so do the orange obstacle circles on the map image. The keep-out
pins of `format=hazards` are read the same way. The keep-out outlines on
the maps are not affected.

The count shown so far went through the same reader, so "0" could mean
either "none" or "none it could read". **The diagnostics download now
tells the two apart** (`cloud.umf_zone_shapes`): how many zones the map
holds, how many the reader found, the field names of the first one, and
its geometry type. It contains no coordinates. If your robot has learned
obstacle zones, a diagnostics download settles the question — please
attach one to an issue.
