# Roomba+ 4.5.1

**The cleaning path stays on the map after the Clean Base empties the bin,
and a 900-series without Smart Map no longer logs a warning after every
mission.**

---

## The cleaning path after the bin is emptied (@nareso)

On a robot with a Clean Base, the *Cleaning path* showed the path while
the robot cleaned and iRobot's coverage dots once it had docked. When
the Clean Base empties the bin, the robot reports that as its own phase
(`evac`). The map took it as the start of a new mission and cleared the
path the mission had just drawn. With nothing left to draw, the picture
fell back to iRobot's record of the mission, and the next mission end
removed the saved path as well.

An evacuation no longer starts a mission on the map, neither the one
after a mission nor one on command.

## No "giving up for this mission" after every 900-series run

After a mission, Roomba+ asks iRobot's cloud twice within about eleven
minutes for the mission's timeline. A robot without Smart Map (a 980 or
another 900-series) never gets one: on the maintainer's 980 it is empty
on all 74 missions in iRobot's history. So every mission ended with
*"newest mission still missing cloud timeline data … giving up for this
mission"* in the log.

On these robots the wait now ends when iRobot's record of the mission
has arrived. If it has not arrived after the second request, the log
says so at info level, and the next scheduled refresh reads it. Smart
Map robots wait for the timeline as before.

## Under the hood

- `callbacks.make_mission_complete_callback`: `_keeps_timeline()`
  (`map_capability == SMART`) and `_caught_up()` (a timeline, or without
  Smart Map the cloud's `durationM`); the frozen baseline uses the same
  check.
- `image.RoombaMapImage.on_message`: phase `evac` or cycle `evac` does
  not open a mission (`_only_evacuating`).

## Tested

- The full suite passes on Home Assistant 2025 and 2026; ruff, the
  typing baseline and the per-module coverage floors pass.
- The new tests fail without the fixes (two per fix).
