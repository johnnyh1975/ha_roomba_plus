# Roomba+ 4.2.10

## New sensor: area cleaned by the last mission

`Missions – Last area` shows the square metres your robot covered on
its most recent completed mission — the counterpart to `Missions – Last
duration`.

`Area cleaned today` still does what it did: it sums the day and resets
at midnight, which is why it could not answer this (@zenyatta80).

Robots that report no area at all, such as the 600-series, leave it
empty rather than showing zero.

## Documented: the `roombapy` import error in your log

`Error occurred loading flow for integration roomba: cannot import name
'Roomba' from 'roombapy'`, repeating every few minutes, is not a fault
in your setup and breaks nothing.

Roomba+ needs the asynchronous `roombapy` 2.x; Home Assistant's
built-in Roomba integration uses the synchronous 1.x interface, and
Home Assistant installs one copy. You see it even without that
integration set up, because Home Assistant finds your robot and tries
to prepare its setup dialog.

TROUBLESHOOTING.md now explains it, with two optional ways to stop the
messages. Resolving it properly means that integration moving to the
async library — a rewrite, not a version bump.

## Measured room times are now used on every robot

Your robot's own measurements of how long each room takes are read from
three different places, depending on whether it has cloud credentials
and which figure is being asked for. The fallback to those measurements
had reached two of the three.

Robots with cloud credentials took the third, which only ever asked
iRobot's cloud — so a room the cloud has no estimate for showed none,
even with a real measurement stored from an earlier mission. The
countdown then worked from one room's figure applied to every room and
ran out early (@Thonno).

A cloud estimate still wins where one exists.

## Measured room times now average, per cleaning mode

Roomba+ kept only the most recent measurement of a room, so the
estimate swung with every run — one tester's bathroom measured 232, 220,
197 and 250 seconds across four missions, and the estimate followed each
one.

It now averages them. Separately per cleaning mode: a mop pass and a
vacuum pass over the same floor take different times, and one figure
covering both describes neither.

Measurements taken before this release count as a single run and settle
from there.

## Naming Smart Map zones: which robot, and where they are

Two things reported against 4.2.9, both still true then.

**The form now names the robot.** 4.2.5 added that to the notice card;
the text you actually read when you open it is a separate string that
was left alone. With two robots there was still no way to tell which
one it meant.

**And unnamed zones now show their number on the map.** The notice asks
you to name zones by number, and the map skipped them precisely because
they had no name — so the one place that could show you where zone 23
is was the one place refusing to draw it. Open the robot's map image
and the numbers are there, next to rooms you recognise (@liblit).

## "Config flow could not be loaded: Invalid handler specified"

That message appeared when the wrong `roombapy` was installed, and it
named nothing: not the library, not the version, not what to do. One
user tried three different Roomba+ releases looking for one that
worked, and concluded the smaller releases must carry fewer
dependencies.

They do not. Every 4.2.x release needs the same `roombapy==2.0.2` and
imports the same class on the same line — 4.2.0 included. The Roomba+
version was never the variable.

Roomba+ now says what is actually wrong: which library is installed,
that restarting Home Assistant installs the right one, and that if it
comes back afterwards, Home Assistant's built-in Roomba integration is
reinstalling the old one over it and needs removing.

The "Two Roomba integrations installed" notice now also triggers on the
library itself rather than only on a configured second integration —
which is the case that was being missed (@bandit254).

## Naming Smart Map zones is a form you can recognise

The old one was a single grey box pre-filled with `2=`, `20=`, `21=`,
one per line, with the format hint below it and off screen. It reads as
a list of results rather than something to type into, and one user
opened it and said so plainly.

Each zone now gets its own labelled, empty field. There is no `id=Name`
format to learn, nothing to delete for a zone you would rather skip,
and no way to get the syntax wrong. Above fifteen zones the text box
comes back, since thirty fields is worse than one box — but empty
rather than pre-filled.

**The notice now names the robot in its title**, so two robots no
longer produce two identical cards.

**And the form says where the naming happens**: the names are yours and
stay in Home Assistant, nothing is renamed in the iRobot app, nothing
is sent to the robot. It also points at the robot's map image, where
unnamed zones now show their number (@liblit).

## A community workaround for the library conflict

@nareso found a way to stop the conflict recurring at all: a folder
named `roomba` under `custom_components/` with no requirements shadows
Home Assistant's built-in integration, so the old library is never
installed. TROUBLESHOOTING.md now carries it, with what it costs.

It suits people who use Roomba+ for every robot and would rather the
built-in one did not come back through discovery. Roomba+ does not ship
it and does not need it — removing the built-in integration through
Settings remains the supported route.
