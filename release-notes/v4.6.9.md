# Roomba+ 4.6.9

**An Essential set up over the iRobot cloud works again.**

Needs **roombapy-prime 0.9.4**; Home Assistant installs it with the
update. Nothing else to do: update and restart.

---

## A Classic robot set up over the cloud keeps running (#265)

Up to 4.6.5, Roomba+ set up the Vac and Combo Essential from the iRobot
account as Prime robots, over the cloud only. 4.6.6 moved them to the
local connection, where they belong, and since then an entry made the old
way did not start: its entities were unavailable, and from 4.6.7 the entry
said it was a Classic robot set up as cloud-only. A user whose Essential
had worked that way lost it with the update. The local connection to an
Essential only worked from 4.6.8 on, so until then there was no way back
at all.

Such an entry now runs over the cloud as it did up to 4.6.5. A repair
issue says the robot is a Classic one, that the local connection is the
more reliable one, and how to move it: *Reconfigure* with the robot's IP
address, password left empty to take it from the account. Nothing moves
by itself.

If the cloud refuses the robot's status, as it did for the three Combo
Essentials in #265, commands still arrive but what Home Assistant shows
stays at its first reading. The repair issue then says exactly that, as
an error rather than advice.

New setups of an Essential from the account still take the local
connection.

## Tested

- The full suite passes on Home Assistant 2025.5; the changed modules'
  tests pass on 2026.10. ruff, the typing baseline and the per-module
  coverage floors pass.
- Setup of a cloud entry for a Classic robot builds it and raises the
  advice; for a Prime robot it does not, and clears it. A refused status
  subscription raises the error for a Classic robot and nothing for a
  Prime one. Each test fails without the change.
- Not yet run on a robot.
