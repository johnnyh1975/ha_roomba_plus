# Roomba+ v3.5.2

> **No code changes.** Identical to v3.5.1 in every respect — same integration, same behaviour, same Config Entry version 25. This release exists only to make v3.5.1's code installable through HACS again.
>
> If you are already on v3.5.1, there is nothing here for you. Updating is harmless and changes nothing.

## Why this release exists

**v3.5.1 became uninstallable through HACS**, and nothing about it changed — the v4 alpha line grew past a threshold in HACS.

HACS asks GitHub for the repository's releases in a single call. GitHub returns **30 per page** by default, and HACS does not paginate: it filters whatever came back in that one response. With v4 in alpha, every one of the 30 most recent releases is a pre-release. With beta versions disabled, all 30 are skipped, HACS is left with an empty list, and it offers the default branch `main` instead.

Selecting `main` then fails with a 404, because this repository sets `zip_release` in `hacs.json` — so HACS looks for a release asset attached to a tag called `main`, which does not exist:

```
Download failed - Got status code 404 when trying to download
.../releases/download/main/ha_roomba_plus.zip
```

The result is a spinning wheel that never completes, on a repository where nothing is wrong.

This release puts a non-pre-release back at the top of the list, inside the window HACS sees. **v3.5.1's code, tagged so HACS can find it.**

Reported by **@pk-1966**, who hit it while trying to install the stable version, worked out unaided that enabling beta versions was a way past it, and then confirmed that the stable version was what he had wanted all along. Without that second message this would have looked like a documentation gap rather than a real regression in installability.

## What this does not fix

**It will happen again.** The alpha line keeps releasing, and thirty more pre-releases will push this out of the window exactly as they did to v3.5.1. If you are on the stable line and a future version stops appearing in HACS, this is why.

The durable fix is to stop the two lines competing for the same 30 slots — a separate repository for the v4 alphas — and that is a larger decision than a tag.

## If you are still stuck

Manual installation works regardless of what HACS offers. Download `ha_roomba_plus.zip` from this release, unpack it so that `manifest.json` sits directly in:

```
config/custom_components/roomba_plus/
```

and restart Home Assistant.

## Which version do you want?

**Stable (this one)** if you have an i-series, s-series, 900-series, e-series or Braava. These are fully supported here, and the v4 alphas add nothing for them.

**The v4 alpha line** if you have a newer Prime-generation robot — a Roomba Max, Combo 405/415, or another model whose app talks to iRobot's V4 cloud protocol. Those robots are **not supported by the stable line at all**; v4 is the only version that will connect to them. Enable "Show beta versions" in HACS and pick the newest `v4.0.0aNN`.

If you are unsure which you have, open an issue with your model number.
