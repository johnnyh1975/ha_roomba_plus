# Roomba+ 4.0.0a41

Requires roombapy-prime 0.3.0b10, which comes with the HACS update.

## Favourites appeared on every robot in a household

@scenicsystemsllc, three Classic robots, same favourite buttons live on
all of them — including **"Vacuum Everywhere" on a mop-only Braava jet
m6.** No map or region argument makes that right.

He read it as #80 having regressed. It had not: **the fix was only ever
in one of two paths, and neither of those was the one that creates
buttons.**

`_favorite_is_for` exists and is correct. It was wired into the
favourites *attribute*. The Prime button builder never called it, and
the Classic button builder — the one his robots use — has no filter at
all.

`/user/favorites` is an **account** endpoint: it returns every favourite
in the household. The Classic loop built a button for each one on every
robot.

Both paths share one function now, with a test asserting that they do.
Two separate implementations is exactly how a fix comes to be applied in
one place and not the other.

## Nothing ever removed an entity

Also his: five stale favourite entities on each robot, `unavailable`
with `restored: true`, deleted in the iRobot app and still listed.

Home Assistant registers an entity the first time it appears and keeps
the row. Nothing in this integration had ever removed one — favourites
or consumable parts.

**The guard matters more than the sweep:** an empty list removes
nothing. A robot with no favourites and a favourites fetch that failed
look identical from here, and treating the second as the first would
empty someone's dashboard on every disconnection.

## Counts were declared as measurements

@chairstacker's `clean_streak` graph showed **9.89725** — for a count of
days.

`MEASUREMENT` tells Home Assistant the value is continuous, so it draws
a line between samples and every point on that line is a number nothing
ever reported. `clean_streak` and `consecutive_clean_skips` are `TOTAL`
now, and the graph steps instead of sloping.

## Calendar

**The weekday can be changed.** a40 made `BYDAY` readable on edits, and
Home Assistant sends no BYDAY when you simply move an entry to another
day — so the preservation rule won every time and the move was
discarded. A schedule with exactly one stored day follows the edit now;
a Mon/Wed/Fri series is still preserved.

**Zone names reach the calendar** without the map view having been
opened. `prime_room_names` is filled when a floor plan is built, so a
session that never drew a map had an empty store.

## Diagnostics

**`region_names`**, showing the merged store and what the last command
carried, separately. Which of the three name sources produced anything
has taken several rounds to establish per robot, and the download did
not carry the answer.
