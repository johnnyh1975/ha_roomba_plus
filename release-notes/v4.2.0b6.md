# Roomba+ 4.2.0b6

Everything in b1 through b5 still applies — see those notes for the
async rewrite. This adds what also went out as 4.1.7.

## The room display now follows the robot

The display worked out room changes from a phase the robot reports
between rooms, and S9-series robots never report one — so the room name
stayed on the first room of the plan for whole missions.

There is a second signal: the robot reports when it is **driving**
rather than cleaning. A drive that ends is a room boundary.

Confirmed twice over before being relied on. The iRobot app names the
value `Traveling`; the robot firmware sets it from an internal
`CLEANING_MODE_TRAVEL`. The advance happens when the drive ends, not
when it starts — and because driving also covers avoiding obstacles and
re-finding position, counting departures would count too many.

New attribute **`room_progress_observed`**: `false` while the room name
is still the plan rather than something seen.

## The cleaning-mode selector only offers what the robot can do

Every robot saw all four modes regardless of its hardware. Picking a
mopping mode on a vacuum stuck, and then the robot vacuumed — no error,
nothing logged (@chairstacker). The robot's own capability report is now
used. Unknown capabilities still show all four.

## Also fixed

- Cleaning a zone on a robot with two maps (@chairstacker)
- A map with no version id was skipped without a word in the log
- `last_cleaned_rooms` reported an earlier mission's rooms during a
  whole-house run (@ScenicSystemsLLC)

## Still what this beta is for

The async rewrite has met little hardware. **The failure to watch for is
a command that silently does nothing** — the robot does not move,
nothing appears in the log.

Settings changes on i/s robots are the least-tested part: passes and
suction never worked there before this line, and nobody has yet
confirmed they hold.
