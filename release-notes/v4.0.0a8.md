# Roomba+ v4.0.0a8

**If you are on v4.0.0a7 with a Prime/V4 robot, please update.** a7 shipped a library version
containing a crash that prevented Prime robots from initialising at all.

## 🚨 Fixed: a7 broke Prime robot setup

a7 pinned `roombapy-prime` v0.1.11a22, which contained a crash in that library's own MQTT
subscription handling. It fired inside the MQTT client's network thread whenever the server
acknowledged a subscription — which is every time — and took the connection down with it. The
symptom was every device shadow timing out during setup:

```
could not seed named shadow 'ro-currentstate' ... within 8.0s
```

Classic robots were unaffected; they do not use that code path. a6 was unaffected because it
pinned an earlier library version.

Found by a field tester who rolled back to a6, confirmed it worked, upgraded again, and reported
both results. That comparison is what made the cause findable.

- **An experimental HTTP header shipped in a7 has been removed.** a22 added a `User-Agent` to the
  cloud connection on an unverified third-party claim; later analysis of the real app disproved it.
  Whether it contributed to a7's failure is unknown — but an unvalidated experiment does not belong
  in the connection path of an integration people run at home. The connection layer now matches
  a6's, which is the version confirmed working.

## Also fixed, from the same investigation

- **Multi-robot accounts were handled by guessing.** When no specific robot was named, the
  library returned whichever one happened to come first — silently. On a two-robot account this
  meant the command-line diagnostics and this integration could end up talking to *different*
  robots without anything saying so. It now refuses to guess and names your options.

- **Household lookup assumed a robot's account id and its BLID are the same string.** On accounts
  where they are not — which does happen — it silently found nothing, which would have broken
  schedule writes for reasons that would have looked like anything but an identifier mismatch.

- **The SKU table that tells Prime robots from Classic ones now lives in the shared library**
  rather than only here. Same behaviour, one copy instead of two -- the diagnostic tools need the
  same knowledge, and a second copy would eventually drift out of step with this one.

## Everything from a7 is still here

a7's own fixes were sound; only the library pin was the problem:

- "Returning" instead of "Cleaning" on the way back to the dock
- Mop tank and bin sensors no longer showing "Home"/"Away"
- New error sensor for Prime robots, including error 671 (clean water tank empty)
- Live map diagnostics, so a blank map now logs what actually arrived

4,194 tests passing.
