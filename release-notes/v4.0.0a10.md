# Roomba+ v4.0.0a10

One small addition, aimed squarely at a problem that has been hard to diagnose.

## Diagnostics now show whether the data stream is actually alive

If your Prime sensors freeze — dock status, mission state, robot status all stuck on old values —
the integration has until now had nothing useful to tell you. Worse, it reported itself perfectly
healthy while doing it.

The reason: a push stream that stops **delivering** without ever **raising** is invisible to error
handling. Nothing fails, nothing logs, the coordinator's own success flag stays true forever. One
tester ended up with frozen sensors and, after updating, no errors at all to report — which reads
like an improvement and is not.

The diagnostics download now includes a `push_freshness` block:

```json
"push_freshness": {
  "last_message_ts": null,
  "seconds_ago": null,
  "note": "no push message has EVER arrived -- the stream is not delivering"
}
```

This is the one field that separates "quiet because nothing is happening" from "quiet because the
connection died". A large `seconds_ago` on a robot that has been active means the stream is gone,
whatever the success flags next to it say.

The underlying timestamp landed in a9; surfacing it where anyone would actually look did not, which
was an oversight.

## Where to find it

Settings → Devices & Services → Roomba+ → the three dots next to your robot → **Download
diagnostics**.

If the note says the stream is not delivering, that is worth reporting — it points at the
connection rather than at any individual sensor.
