# Roomba+ 4.1.2

Four fixes from the field, all reported against 4.1.1 within a day of it
shipping. Nothing to reconfigure.

## Cleaning a zone failed on a robot with two maps

Selecting a zone and pressing **Clean selected room** gave:

> This robot has 2 maps and is not currently reporting which one it is
> on, so there is no way to tell which floor's rooms you mean.

Rooms worked; only zones failed (@chairstacker). Room ids carry the map
they belong to and zone ids did not, so nothing told the command which
floor it was for — and rather than guess, it refused. The advice in that
message could never have helped: the map was known, it just was not in
the id.

Zone ids now carry their map, the same way room ids always have.

## Zones on other maps had no name at all

The all-maps name source read a map's `regions` and ignored its `zones`
— the two sit side by side in the same document. Roomba+ also now reads
the map *version* document, which is where iRobot keeps region names for
rooms **and** zones, and which nothing had ever called.

That closed a real gap: nine zones across two maps where there had been
a partial list.

## A Roomba 980 was told to replace a bag it does not have

`binary_sensor.<robot>_maintenance_due` turned `on` with
`due: ["clean_base_bag"]` on a 900-series, which charges on a plain dock
(@liblit, R980020, with diagnostics).

Every per-part entity was already suppressed for those robots. The
maintenance-due path was not — it walked all four consumable roles
regardless, and the cloud could not contradict it because there is no
cloud record for a part the robot does not have. It fell through to the
local hour count, which measures **runtime** rather than bag use, so the
bag went due at 30 hours.

**Side brushes are not gated**: a 980 has one, and skipping it would
silence a real reminder on every robot without a Clean Base.

## A zone was missing until Home Assistant was restarted

@theChef163's zone "Litter" never appeared in the selector, while Home
Assistant's own area-mapping dialog found it and cleaning through that
worked. His diagnostics carried the name all along.

The dialog reads live; the selector read once when the entity was added
— before any map had been drawn. Zone names arrive when the map image
builds a floor plan, so the first read was always too early for them.

There was already a signal for exactly this, added when the per-region
sensors had the same problem. The selector listens to it now.

## The room/zone list stayed frozen, and a partial list looked complete

Two smaller faults behind an 18-versus-17 mismatch between the selector
and the area-mapping dialog (@chairstacker):

The selector read its list once at startup and never again, so a map
retrained in the app never showed up. It now reloads when the robot's
map state changes.

And a map whose names could not be fetched was skipped silently at debug
level, producing a shorter list indistinguishable from a full one. That
is a warning now, and it says which map is missing.
