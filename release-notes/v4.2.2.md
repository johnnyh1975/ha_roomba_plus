# Roomba+ 4.2.2

One real fix, and the quality badge finally matching what the
integration declares.

## Cleaning a room on a second map could fail outright

On a robot with more than one map, cleaning rooms on the map the cloud
does not call active sent the robot a map id and a map version that
belong to **different maps**. It cannot localise against that pairing,
so it refuses with "Smart Map localization failed" and stays on the
dock — accepted, then nothing.

Two code paths carried the fault in mirrored forms. One attached the
active map's version to whatever map was requested; the other put the
active map's id on another map's regions. Both now send the requested
map together with that map's own version.

Invisible on a single-map robot, where the two are always the same map.
That is most robots, which is why it lasted. Reported by a tester whose
i7+ refused to start while sitting on its own dock, having been moved
nowhere (@Thonno).

## The Platinum badge

4.2.1 declared Platinum in its manifest while the README still showed
Gold — in three places, one of which listed every Platinum rule as met
in the same sentence as the Gold claim. The comparison table said Gold
too.

All corrected, and a build check now compares the badge and the prose
against the manifest, so they cannot drift apart again.

## Under the hood

The room-transition logic gained a test built from a real three-room
mission on hardware this project has never seen, contributed by a
tester running their own stack (@AlakazipLabs). It confirms the rule
that a drive ending within a minute of entering a room is repositioning
rather than a boundary — their robot's 12-second drive off the dock is
exactly that case, and counting it would put the display one room ahead
for the rest of the run.

Their archive also independently confirms three readiness values that
had been named from firmware constants rather than from observed
behaviour.
