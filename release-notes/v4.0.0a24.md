# Roomba+ v4.0.0a24

Requires roombapy-prime **v0.2.0b12**.

A small release with one idea: a command that never left should not look like a command the robot
ignored.

## Commands now say when they were not delivered

`send_simple_command()` reports whether the broker acknowledged the publish. **Every call site in this
integration threw that away** — start, pause, dock, locate, and all four dock buttons.

So a command that never reached iRobot's cloud looked exactly like one the robot chose to ignore: the
button press succeeded, the service returned, and nothing happened. A field report described it as
"no reaction from the logo" for start, locate and dry pad alike — three controls, one silent
transport, and four days spent looking at the controls.

Undelivered commands now raise, and say that this is a connection problem rather than a refusal by
the robot.

**A test asserts that every call site goes through the check**, and it immediately found one I had
missed while making the change: the Locate button, which was exactly one of the three that had been
reported as unresponsive.

Paired with b12, which makes the two matching failures in the transport visible: a subscription that
was never sent, and one that was never acknowledged.

## Nothing else changed

Everything in a23 stands.

4,874 tests.
