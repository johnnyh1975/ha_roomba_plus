# Roomba+ 4.3.0b6

**A beta.** Everything in [4.3.0b5](v4.3.0b5.md), plus a rebuilt cloud
connection for Prime robots and the fixes from the stable release
[4.2.18](v4.2.18.md).

Needs *Show beta versions* in HACS. Built on **roombapy-prime 0.5.0b2**.
b1 to b5 were built on 0.4.0.

---

## Prime robots: a rebuilt cloud connection

**Only Prime robots** (Roomba Max, Combo/Plus 400-series and similar).
Classic robots don't use this connection.

roombapy-prime 0.5 runs the robot's cloud connection on Home Assistant's
own event loop instead of a thread of its own. It uses aiomqtt, which
Home Assistant's built-in Roomba integration already uses. What goes
over the wire is unchanged.

The larger part is how the connection gets through a drop. Three
reviews of the new code found the following, several of them in the
current stable release as well:
- **A robot could go silent until Home Assistant restarted.** A drop at
  an unlucky moment, such as right after a reconnect, was missed, and
  the log still said "watch resumed".
- **The hourly token renewal no longer shows as a drop.** A real drop
  logs one "dropped" line and one "resumed" line, where it used to log
  one of each per watcher. The "3 disconnections in five minutes"
  warning no longer fires on every ordinary drop.
- **No reconnect loop when the server never confirms a subscription**
  ("no SUBACK"). The robot tries at most twice, then carries on.
- **Unloading or stopping Home Assistant closes the connection for
  good.** Before, it could leave a hidden connection behind that then
  competed with the next one for the same robot.

Details: [roombapy-prime 0.5.0b1](https://github.com/johnnyh1975/roombapy-prime/blob/dev-0.5/release-notes/v0.5.0b1.md).

## Prime robots renew through the account's login

4.3.0b1 shared the first login of an account between all its robots,
and said that Prime robots would follow for their token renewal with
roombapy-prime 0.5. This beta does that:
- **A Prime robot whose token is due takes a fresh login another robot
  has just made**, and otherwise logs in once for every robot asking.
  Robots that started from one login renew with one login, not one
  each.
- **The robot's map requests relog through the account too.**
- **A failed login answers for half a minute** instead of every robot
  trying again. Against a locked account, every attempt extends the
  lock.

## From 4.2.18: switching the maintenance list on

Switching the maintenance to-do list on (new for Classic robots in b5)
made the reload fail with "Config entry was never loaded!", and the
list only appeared after a restart (@ScenicSystemsLLC).

- **Unloading takes down exactly what setup loaded.** Before, it rebuilt
  the platform list from the new options and tried to unload a platform
  that had never been loaded.
- **The switch reloads the entry on purpose.** Before, it only did so by
  accident. Saving the form without changes no longer reloads.

## From 4.2.18: the rooms map

On Classic robots:
- **"Draw room names" now takes effect when you save it.** The map image
  was kept until the map itself changed, so switching names on, or
  naming a zone, showed nothing new before that. The Prime rooms map is
  redrawn on saving too.
- **The names are the ones you use everywhere else.** In order: your own
  alias, the name from your iRobot account, then a name typed into the
  naming notice.
- **A room without a name shows its number**, as on the Prime map: the
  naming notice lists zones by number.

Names on the map are off by default, because the xiaomi-vacuum-map-card
draws its own. Switch them on under Configure → Connection settings →
*Draw room names on the map image*. The feature guide had this listed as
on by default (@liblit).

## What to test

**Prime robots, over a day or two:**
- Leave it running. Status and missions should keep arriving, and the
  hourly token renewal should leave **no** "dropped" line in the log.
- Restart your router, or unplug the network for two minutes. Expect
  **one** "MQTT connection dropped" line and **one** "watch resumed"
  line, then data again.
- Run a cleaning with the live map open.
- Reload the integration and restart Home Assistant. Afterwards there
  should be no drops every few minutes and no ERROR lines from
  `roombapy_prime`.
- If you have several Prime robots on one account: after an hour or two,
  check that the log shows one login when the tokens run out, not one
  per robot.

**Several robots on one account, either generation:**
- Restart Home Assistant and check that there is one login, not one per
  robot.
- Change the iRobot password and enter it once.
- After adding the first robot, the others should be offered under
  *Discovered*.
