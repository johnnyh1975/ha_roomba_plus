# Roomba+ 4.0.0a47

Requires roombapy-prime 0.3.0b18, which comes with the HACS update.

Five bugs with one shape, the check that finds the sixth, and zones
finally reaching the places that were built for them.

## The shape

Every one of these was a Prime code path reading a source that either
does not exist on a Prime robot, or exists and carries only part of the
answer:

- **The per-room sensors created nothing.** The option read
  `cloud_coordinator.regions_by_pmap`; a Prime config entry has no
  `cloud_coordinator` at all. A tester ticked the box, ran a zone
  mission, reloaded, and got not one entity.
- **The room name in the `roomba_plus_room_completed` event was always
  empty.** Same source, same reason — so "Kitchen finished" arrived
  without the kitchen.
- **The device tracker showed a raw region id during a zone clean.**
  Its name cache came from `available_rooms()`, which reads
  `rooms_metadata` and therefore knows rooms but not zones. The names
  were in the diagnostics download the whole time; there was nothing to
  look them up with.
- **Zones could not be mapped to a Home Assistant area.** The segment
  list was built from the same source, so a zone was never in the list
  the mapping dialog shows. Classic has offered its zones all along.
- **The cloud-coverage fallback was gated on `cap.pose`** — the field
  lewis firmware sets on robots that never send a pose, so it stood
  aside on exactly the robots needing it.

None of these was carelessness at the time. A better source appeared
later — `prime_room_names`, which holds rooms and zones together — and
the places already reading the older one were never revisited. Each
looked correct in isolation; each returned a subset or nothing.

Four of the five produced no error and no complaint. They were found by
going looking.

## The check

`scripts/check_prime_sources.py` fails the build when Prime code reads a
Classic-only source. It found one of the five itself.

Exemptions carry a written reason rather than sitting in a silent list:
`prime_room_map.py` reads the Classic coordinator deliberately, to merge
Classic names in on a household running both generations.

## Zones on the map

A saved clean zone carries a polygon beside its name, and nothing read
it — so a zone had a name and no shape to attach it to. They are drawn
now, outlined rather than filled: a zone sits inside a room, and a fill
would hide the room it belongs to.

The `map_clean_zones` option that is supposed to control this was read
in the options dialog and nowhere else.

## Setting up with an iRobot account

The setup option said "for newer models with no local setup, e.g.
Combo", which tells an i7 owner it is not for them. It is in fact the
fallback for any robot whose password cannot be fetched automatically.

A forum user with two i7s read that, concluded it did not apply, and ran
a third-party script to extract his password by hand. He did the right
thing and the interface told him not to. Reworded, in all eight
languages.
