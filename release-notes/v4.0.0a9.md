# Roomba+ v4.0.0a9

Fixes for Prime robots from field testing, plus everything the companion library gained alongside
them.

## Sensors could freeze without anything noticing

A tester's mission-event sensor stuck on one value and the dock status stopped updating — both at
once, while the integration reported itself perfectly healthy.

Two independent sensors stopping together points at the data stream rather than at either sensor,
and nothing was watching the stream. The reason: the freshness timestamp that every staleness
check in this integration relies on was only ever written by the Classic code path. For Prime
robots it stayed at zero forever, so those checks sat permanently silent.

Worth explaining why the existing error handling could not catch this. A stream that stops
**delivering** without ever **raising** is invisible to an error handler — it simply never yields
again. A timestamp is the only thing that separates "quiet because nothing is happening" from
"quiet because the connection died". Both Prime data streams now write it.

## "Returning to dock" could stick after a mission ended

The same tester saw the vacuum's status stay on "Returning to dock" for minutes after the robot had
finished, while the dock sensor had already gone back to ready.

The root cause is not confirmed — no capture yet exists of a robot in that exact stuck state. What
this release adds is the corroboration rule this project already learned the hard way for error
codes: if the reported phase says "returning" while no cleaning cycle is active, the mission is
over. The correction only ever turns a wrong "returning" into "docked", never the reverse, so a
genuine trip back to the dock cannot disappear.

## Multi-robot accounts

The companion library used to pick whichever robot came first when none was named, silently. On an
account with a Roomba 980 and a Prime robot, that meant commands going to the 980 — which cannot
speak the Prime protocol at all.

This integration was never affected: it always asks for a specific robot. But the command-line
diagnostic tools were, and the two could end up talking to *different* robots without anything
saying so. Both now name the robot explicitly.

## From the companion library (v0.1.11a27)

All connection handling lives there, so these apply here too:

- Publishing and subscribing now verify the connection is alive first — previously only reading
  did. Sending into a dead connection produced no error and no delivery confirmation.
- Concurrent watchers no longer tear down each other's shared connection.
- Keepalive lowered from 300 to 60 seconds; at 300, a broken connection went unnoticed for up to
  450 seconds.
- The live map arrives zlib-compressed and was being fed to the protobuf parser raw — the likely
  cause of blank live maps.

## Internal

Nothing user-visible, but worth recording:

- **`__init__.py` shrank from 3,632 lines to 1,487.** Config-entry migrations moved into their own
  `migrations.py`. Migrations only ever grow — every historical version has to stay forever — so
  keeping that permanent body in the same file as the setup logic made both harder to read. No
  behaviour changed; a test guards the re-export Home Assistant relies on.
- **`docs/ARCHITECTURE.md` added**, including an honest list of the remaining weaknesses.
- **Test coverage** on the config flow and the core sensor base class raised where it mattered most
  — the setup error paths a user hits before they have any entity or log to inspect.

4,240 tests passing.
